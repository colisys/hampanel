# 首次连接

安装受控端后会得到一份注册凭据 JSON，客户端用它建立 mTLS 连接。里面包含：

- CA 证书、客户端证书与私钥
- endpoint（实际监听地址与端口）
- 随机入口前缀

## 导入

在客户端启动页粘贴凭据 JSON，或选择凭据文件导入。客户端会自动使用其中的 endpoint、端口与前缀，不需要手动填写。

## 核对指纹

导入前，通过一个独立于凭据传输的渠道核对 CA 与服务端证书的 SHA-256 指纹，例如在服务器上直接执行：

```bash
openssl x509 -in /etc/hampanel/tls/ca.crt -noout -fingerprint -sha256
```

核对一致再导入。首次导入属于信任首次使用（TOFU），所以凭据本身的传递渠道要可信。

## 入口前缀

初始化时默认生成 `/` 加 96 位随机 token 的前缀。除健康检查等少数接口外，请求都必须带该前缀，否则返回 404。

前缀只是额外的隐蔽层，**不能替代 mTLS**。真正的访问控制来自客户端证书校验，建议同时用防火墙限制管理端口的可达范围。

## 多主机

客户端可以保存多台主机，在侧栏切换。断开连接只结束当前会话，凭据仍保留；移除主机需要单独确认。

## 连不上时检查

| 现象 | 检查项 |
| --- | --- |
| 握手直接失败 | 防火墙/云安全组是否放行受控端端口；凭据是否对应这台主机 |
| 连接成功但接口 404 | 入口前缀是否随凭据一起导入 |
| 客户端提示证书不匹配 | 服务端证书是否重新签发过；重新获取凭据并核对指纹 |
| 端口不通 | 受控端服务是否在运行：`systemctl status hampanel` |

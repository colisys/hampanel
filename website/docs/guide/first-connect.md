# 首次连接

受控端安装完成后会生成一份注册凭据 JSON，客户端用它建立 mTLS 连接。内容包含：

- CA 证书、客户端证书与私钥
- endpoint（监听地址与端口）
- 随机入口前缀

## 取得凭据

| 安装方式 | 凭据位置 |
| --- | --- |
| Linux 本地安装 | `/etc/hampanel/enroll.json` |
| Windows 本地安装 | `C:\ProgramData\hampanel\enroll.json` |
| `hampanelctl` 远程安装 | 本机 `--out` 指定的路径；默认 `hampanel-<主机名>.json` |
| 客户端 SSH 安装 | 自动导入，无需手动取 |

需要从服务器取出时，用 `scp` 等可信方式复制凭据，并限制接收设备上的文件权限。

## 导入

在客户端启动页粘贴凭据 JSON，或选择凭据文件导入。客户端会自动使用其中的 endpoint、端口与前缀，不需要手动填写。

导入后在 **设置 → 常规 → 连接** 点击 **测试连接**，确认返回连接正常；「证书指纹」卡片会列出 CA 与服务端证书的 SHA-256。

## 核对指纹

首次连接后，通过独立于凭据传输的渠道核对 CA 与服务端证书的 SHA-256 指纹。在 Linux 服务器上执行：

```bash
openssl x509 -in /etc/hampanel/tls/ca.crt.pem -noout -fingerprint -sha256
openssl x509 -in /etc/hampanel/tls/server.crt.pem -noout -fingerprint -sha256
```

与客户端 **设置 → 常规 → 证书指纹** 中的值比对；证书重新签发后需重新核对。首次传输凭据时使用可信渠道。

## 入口前缀

初始化时默认生成 `/` 加 96 位随机 token 的前缀。除健康检查等少数接口外，请求都必须带该前缀，否则返回 404。

前缀是减少被扫描概率的隐藏层，访问控制由客户端证书校验完成；建议同时用防火墙限制管理端口的可达范围。

## 多主机

客户端可以保存多台主机，在侧栏切换。切换只改变当前管理对象，各主机的连接各自独立。断开连接只结束当前会话，凭据仍保留；移除主机需要单独确认。

## 连不上时检查

| 现象 | 检查项 |
| --- | --- |
| 握手直接失败 | 防火墙或云安全组是否放行受控端端口；凭据是否属于这台主机 |
| 连接成功但接口 404 | 入口前缀是否随凭据一起导入 |
| 客户端提示证书不匹配 | 服务端证书是否重新签发过；重新取得凭据并核对指纹 |
| 端口不通 | 受控端是否在运行：`systemctl status hampanel`、`Get-Service hampanel` |
| 能连接但操作报权限错误 | 受控端是否以 root / Administrator 运行 |

服务端时间偏差过大也会让握手失败，可对照 `date -u` 与客户端时间。

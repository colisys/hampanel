# 安全模型

## 双向 TLS

连接由服务端 CA 签发的证书建立：

- 服务端只接受由本项目 CA 签发、CN 以 `hampanel-client` 开头的客户端证书。没有有效证书，TLS 握手直接失败。
- 客户端固定信任该 CA，不提供「忽略证书错误」选项。
- TLS 最低 1.2，优先 1.3。
- 客户端同时校验证书链、主机名与保存的指纹。

没有密码登录流程，也没有对外提供的 Web 管理页面。

## 凭据与指纹

安装时生成：

- CA 证书与私钥
- 服务端证书
- 客户端证书与私钥
- endpoint 与随机入口前缀

以上内容打包为 `enroll.json`。该文件包含客户端私钥，导入后即可管理服务器。

**指纹核对**：通过一个与凭据传输不同的渠道核对 CA 与服务端证书的 SHA-256 指纹。首次导入属于信任首次使用（TOFU），能防的是凭据到手之后的替换，防不住凭据传递过程中的主动中间人。所以传递渠道本身要可信。

证书轮换后需要重新核对指纹。

## 入口前缀

初始化时默认生成 `/` 加 96 位随机 token 的前缀。除健康检查等少数接口外，请求必须携带该前缀，否则返回 404。

前缀的价值是减少被扫描到的概率。它不是访问控制，**不能替代 mTLS**。

## 权限边界

| 项 | 说明 |
| --- | --- |
| 运行身份 | Linux 以 root、Windows 以 Administrator 系统服务运行 |
| 私有材料 | 私钥 `0600`，Linux TLS 目录 `0700`；Windows 使用 `%ProgramData%` 的 ACL |
| 命令执行 | 以 argv 直接执行，不经过 shell |
| 参数校验 | 容器名、单元名、UFW 规则、任务名做白名单校验 |
| PowerShell | 只拼接校验过的端口、IP、动作与转义后的显示名，不接受任意脚本 |

因为受控端本身拥有系统管理员权限，真正的边界在网络层：建议只监听内网，或用防火墙限制管理端口的可达范围。

## 高权限应用

应用商店里有几个应用会影响宿主机安全边界，部署前需要明确这一点：

| 应用 | 权限 |
| --- | --- |
| Act Runner | 挂载容器引擎 socket，等同于宿主机控制权 |
| EasyTier | 宿主网络 + TUN + `NET_ADMIN`，参与宿主路由 |
| vLLM | 需要 GPU 设备访问 |

只在你信任的范围内使用这些应用。

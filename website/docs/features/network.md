# 网络接入与防护

SSH、WAF 和防火墙从[安全中心](/features/security)进入；端口穿透在一级导航中。

## SSH

管理**目标机**的 sshd。从 **安全中心 → SSH 访问** 进入后先查看当前状态与端口；修改前保留一条现有 SSH 会话，在宿主防火墙与云安全组提前放行新端口，再保存并从另一终端验证新连接。页面分三个标签页：

- **概览**：sshd 状态与生效配置；修改端口、root 登录、密码登录、公钥登录策略。
- **密钥**：按用户管理 `authorized_keys`。
- **日志**：查看 journal、auth 与文件日志，可选择写入 rsyslog 文件。

配置修改先校验，失败会回滚。改端口前先在防火墙和云安全组放行新端口。

## 防火墙

从 **安全中心 → 防火墙** 查看现有规则，再新增放行或拒绝规则。修改前记录面板和 SSH 当前使用的端口，先加放行规则，再测试新连接，最后才删除旧规则；防止把自己锁在服务器外。

- Linux 对应 UFW。
- Windows 对应系统防火墙。

这里管理宿主防火墙。云厂商安全组与 WAF 各自独立生效，需要分别配置。

## WAF

在 **安全中心 → WAF 边缘** 配置监听地址与源站，先用检测模式观察日志和误报，再按域名切换阻断模式。上线前确认域名指向 WAF、源站可由 WAF 访问，并在源站防火墙限制绕过 WAF 的直连。Linux 上的 WAF 使用 Caddy + Coraza + 内嵌 OWASP CRS：

- 配置监听地址与上游源站。
- 按 Host 或通配域名设置策略。
- 三种模式：关闭、检测（只记录）、阻断。切换阻断需要确认。
- 配置 TLS、GeoIP/GeoSite。
- 可选 TypeSafe 风险复检与风险日志。
- **暴力破解封禁**：对反复失败的登录请求按来源计数，超过阈值即临时封禁。
- **浏览器指纹**：为请求生成指纹，便于识别同一来源的自动化工具。

上线时同步调整现有站点的监听配置，并在源站防火墙限制直连。

TypeSafe 是外部复检服务，启用后请求数据会发送到该服务。相关密钥通过 systemd-creds 管理。

## 端口穿透

在**桌面管理端**打开 **端口穿透**，选择转发类型，填写本机监听端口、远端目标与 SSH 连接信息；启动后先在本机回环地址测试，使用结束即停止。隧道在桌面客户端运行：

| 类型 | 说明 |
| --- | --- |
| 本地 SSH 转发 | 把远端端口映射到本机 |
| 反向 SSH 转发 | 把本机端口暴露到远端 |
| 动态 SOCKS | 本机 SOCKS 代理，要求两端都是 Linux |
| socat 中继 | 本机端口转发，要求本机安装 socat |

- 监听地址限定回环。
- SSH 转发支持一层跳板，可使用私钥或 agent。
- 移动端不显示该功能。

隧道在客户端运行；应用商店里的 FRPS / frpc 则作为常驻服务安装在服务器上。

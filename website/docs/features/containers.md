# 容器与运行环境

## 引擎

首次启动时探测 Docker，未安装则回退 Podman，并把结果写入 `config.json` 的 `container` 字段。之后固定使用该值，不再每次请求重新探测；手动修改该字段并重启即可切换。

引擎缺失时，容器页会给出安装引导。

## 容器

打开 **容器**，先在概览确认引擎已就绪。需要部署新容器时，从镜像创建并核对端口映射、卷挂载和环境变量；已有容器可打开详情查看状态、日志或终端。删除容器前确认数据是否保存在独立卷内。

- 从镜像创建容器，按配置重建。
- 启停、删除。
- 查看 inspect、统计与日志。
- 添加备注，进入终端，管理容器内文件。
- 把容器提交为镜像。

## 编排

进入 **容器 → 编排** 创建项目并填写 Compose 配置；部署后从项目详情检查服务状态与日志。也可以接管已有项目，编辑前保留原配置副本。Compose 项目支持创建、接管已有项目、编辑、启停、拉取镜像、查看日志与删除。

应用商店部署的应用也以 Compose 项目形式出现，可以在编排页看到并管理。

## 镜像

- 搜索、拉取、推送、更新、打标。
- 构建镜像。
- 导入与导出。
- 清理悬空镜像。

另可管理镜像仓库凭据与登录同步。

## 网络与卷

在容器页的网络或存储卷子页创建、查看、删除自定义网络与数据卷。**删除卷前先备份**：数据卷删除不进入文件回收站，也不保留历史版本。

## Docker 设置

管理引擎级配置：

- 镜像加速
- 私有仓库
- IPv6
- 日志驱动与大小
- iptables
- Live Restore
- cgroup 驱动
- NVIDIA 运行时
- socket 路径

修改 daemon 配置与修改单个容器是两件事。合并写入前会备份，保存后可选择重启引擎。重启会影响已有负载。

::: tip 引擎差异
Docker 与 Podman 共用容器、镜像、网络、卷的基本操作；Docker 专项设置仅在 Docker 引擎下生效。
:::

## 运行环境

进入 **运行环境**，选择语言和版本，再配置镜像源与扩展后创建。先确认宿主 Docker 已就绪；创建与构建的进度可以在 **任务** 页查看，失败时先读任务输出。建成后打开环境的 **管理** 页查看日志、配置和进程，再决定是否调整并重建。

以宿主 Docker 创建隔离的语言环境，支持 Node、Python、Java、Go、PHP、Ruby、.NET 与自定义镜像。

- 选择推荐版本、注册表 tag 或自填版本。
- 配置包源与扩展。
- 查看日志、编辑配置、重建环境。
- 按 Supervisor 进程启停。

运行环境在容器内安装语言运行时；扩展或包源变更可能触发重建。除 PHP 预设外，其余预设需在配置中写明启动命令。

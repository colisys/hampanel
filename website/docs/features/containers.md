# 容器与运行环境

## 引擎

首次启动时探测 Docker，未安装则回退 Podman，并把结果写入 `config.json` 的 `container` 字段。之后固定使用该值，不再每次请求重新探测；手动修改该字段并重启即可切换。

引擎缺失时，容器页会给出安装引导。

## 容器

- 从镜像创建容器，按配置重建。
- 启停、删除。
- 查看 inspect、统计与日志。
- 添加备注，进入终端，管理容器内文件。
- 把容器提交为镜像。

## 编排

Compose 项目支持创建、接管已有项目、编辑、启停、拉取镜像、查看日志与删除。

应用商店部署的应用也以 Compose 项目形式出现，可以在编排页看到并管理。

## 镜像

- 搜索、拉取、推送、更新、打标。
- 构建镜像。
- 导入与导出。
- 清理悬空镜像。

另可管理镜像仓库凭据与登录同步。

## 网络与卷

创建、查看、删除自定义网络与数据卷。删除卷前需确认，因为数据不可恢复。

## Docker 设置

管理引擎级配置：

- 镜像加速
- 私有仓库
- IPv6
- 日志驱动与大小
- iptables
- Live Restore
- cgroup 驱动
- NVIDIA 运行时
- socket 路径

修改 daemon 配置与修改单个容器不同。合并写入前会备份，保存后可选择重启引擎。重启会影响已有负载。

::: tip 引擎差异
Docker 与 Podman 的共性是容器、镜像、网络、卷的基本操作。部分 Docker 专项设置与引擎特有的行为不要求两边完全等价。
:::

## 运行环境

以宿主 Docker 创建隔离的语言环境，支持 Node、Python、Java、Go、PHP、Ruby、.NET 与自定义镜像。

- 选择推荐版本、注册表 tag 或自填版本。
- 配置包源与扩展。
- 查看日志、编辑配置、重建环境。
- 按 Supervisor 进程启停。

运行环境是在容器里装语言运行时，不是在宿主机直接安装。扩展或包源变更可能触发重建。非 PHP 预设不会自动启动业务进程，需要在配置里写明实际启动命令。

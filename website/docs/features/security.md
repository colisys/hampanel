# 安全中心

安全中心把原本分散的安全相关入口收在一页：SSH 访问、WAF 边缘、防火墙、Fail2ban 封禁，以及六项更主动的能力。

::: tip 先看能力探测结果
打开页面时受控端会探测本机实际具备的能力：eBPF / bpftrace、`chattr`、QEMU、`nft`、`ufw`、SELinux，以及是否以 root 运行。不具备的入口会直接禁用并说明原因，而不是点了才报错。
:::

## 扫描感知

被动采集主机收到的半开连接（SYN），把「一个来源在窗口内触达了多少个不同端口」作为扫描信号，超过阈值即自动拉黑。

- **探针**：`bpftrace` 脚本挂在 `tcp_v4_rcv` / `tcp_v6_rcv`，按「来源 + 端口」聚合，每 5 秒输出一行 JSON。选择 `bpftrace` 而非编译 libbpf 对象，是因为后者要求构建机内核头与运行内核一致。
- **默认阈值**：单来源 12 个不同端口。命中后写入 `ufw` 拒绝规则并记录到本机封禁清单。
- **运行方式**：探针由受控端监管，进程退出即重启；daemon 重启后已安装的探针自动恢复。
- **操作**：安装 / 启动 / 停止探针，查看观测到的连接，解除单个来源的封禁。

## 主机探测

主动向目标发包做端口、服务与系统指纹扫描。

- 目标只接受字面 IPv4 / IPv6 或 RFC 1123 主机名；网段、列表、任何可能被读成 nmap 参数的值都会被拒绝。
- `nmap` 以 argv 调用，不经过 shell；IPv6 目标自动加 `-6`。
- 系统指纹需要 root，且 IPv6 的指纹库覆盖较差，结论为空时报告会如实写出。
- 可叠加 Shodan InternetDB 的免密钥被动情报；它没有 IPv6 索引，v6 目标只返回主动扫描结果。

扫描耗时以分钟计，因此注册为任务执行，结果写入任务详情。

::: warning 授权范围
探测会暴露面板自身的 IP。只对你有权测试的目标使用；被动情报来自第三方，仅作参考。
:::

## 蜜罐

在 QEMU/KVM 中运行一台隔离的 guest，用宿主机自带内核加 busybox 构建 initramfs，不需要下载任何镜像。

- **硬件身份复刻**：CPU 型号、核心数、内存与 DMI 字符串读自宿主机，攻击者看到的是一台「合理」的机器。但没有任何设备透传：没有 PCI 直通，没有宿主块设备，磁盘是自建的 qcow2。
- **网络隔离**：QEMU 用户态网络，guest 只能通过转发端口被访问，无法到达宿主所在局域网；每个会话生成独立的 `52:54:00` 前缀 MAC。
- **资源上限**：CPU 最多 8 核，内存取宿主机的一半并封顶 8 GiB，guest 不能把宿主机拖垮。
- **诱饵内容**：每次构建都会生成一套看起来像真机器的内容——随机主机名与发行版、`/etc/passwd` 与 `shadow`、`authorized_keys`、带真实运维命令的 `.bash_history`、随机主题的登录页、`robots.txt`、一份「忘了删」的备份配置，以及格式正确的 nginx / auth 日志。全部为伪造，且同一次构建内互相吻合。

构建镜像与启动 guest 都走任务队列，不占同步请求。页面提供运行中的 guest 控制台。

## 文件防篡改

用 `chattr +i`（不可变属性）保护关键路径：带该属性的文件即使 root 也无法改写、重命名或删除，只有清除属性后才能维护。

- 保护目录时自动递归，因为只给目录本体加属性仍可在其中新建与重写文件。
- 受保护路径记录在受控端的清单里。daemon 启动时逐条复查，属性丢失会重新应用并记录日志——重挂载、镜像重建或 fsck 都可能静默清除属性，静默失去保护正是要避免的情况。
- `chattr` / `lsattr` 缺失时入口禁用。

## 主机加固

把常被漏掉的杂项集中在一页，每项都先读现状再写入受管文件，重启后依然生效。

| 项目 | 说明 |
| --- | --- |
| 空链接 | 精确匹配目标无法解析的链接，删除前再解析一次，避免误删刚修好的链接 |
| 默认 umask | 写入 `pam_umask` 使用的配置文件；校验要求「其他用户必须失去写权限」，`027` 有效、`000` 被拒绝 |
| at / cron | 写 `*.allow` 并删除 `*.deny`，用户名逐条校验 |
| sudo | 只写入 `use_pty` 与 `!visiblepw`，写入后用 `visudo -c` 校验，不通过则回滚 |
| 内核参数 | 只暴露 15 个有明确安全含义且有安全取值的参数；取值写入 `sysctl.d` 并用 `sysctl -w` 立即生效 |

`net.ipv4.ip_forward` 被标为**需人工判断**，不包含在「应用全部建议值」里：在容器宿主或路由器上关闭转发会直接破坏网络。

## SELinux

只按能力上报，不假定存在。宿主使用 AppArmor（例如 Ubuntu 默认）时页面只显示「未启用」，不会给出无法生效的开关。

有 SELinux 的主机按五个标签页打开，避免把上百项布尔值平铺成一屏：

- **概览**：当前 / 开机模式、策略类型、模块数量与列表。
- **布尔开关**：带搜索的逐项开关，只接受策略实际声明的名字。
- **文件上下文**：本地定制可增删；保存后执行 `restorecon -R` 重打标签，因为 `semanage` 只记录规则、不改现状。
- **端口标签**：查看端口与类型的绑定，可绑定 / 解绑。
- **拒绝日志**：展示权限、`tclass`、源 / 目标上下文与路径。

### 首次初始化

在从未打过标签的主机上直接切换到 enforcing 会让机器无法启动。因此初始化是页面上一个显式步骤：

1. 为面板自身路径与容器存储写入文件上下文规则。
2. 对全盘执行 `restorecon -R`，但**显式排除容器存储**——overlay 层里是完整的 guest 文件系统，把宿主策略盖上去会让容器内的文件失去可执行权限。
3. 写入就绪标记。

未完成初始化时，enforcing 开关不可用，受控端也会拒绝「未初始化 → 切 enforcing」这条路径。

### 重打标签之前禁止重启

未初始化的主机重启后会回到无法启动的状态。因此就绪标记存在之前，面板拒绝一切会把主机带下去的操作：对 `reboot` / `poweroff` / `halt` / `kexec` 目标及其服务形态一律返回可读错误，并指向初始化入口；普通服务不受影响。主机没有 SELinux、没有 `semanage` 或已完成初始化时一律放行。

# 安全中心

安全中心集中提供 SSH 访问、WAF 边缘、防火墙、Fail2ban 封禁，以及扫描感知、主机探测、蜜罐、文件防篡改、主机加固和 SELinux。打开页面后先查看能力探测状态；缺少依赖时相应入口会显示不可用原因。

## 概览卡片

| 卡片 | 作用 |
| --- | --- |
| SSH 访问 | 跳到 SSH 管理，查看 sshd 状态与生效配置 |
| WAF 边缘 | 查看 WAF 运行状态，进入 WAF 页面 |
| 防火墙 | 当前规则数量与状态 |
| Fail2ban 封禁 | 封禁数量与阈值，可直接解封 |

这四项的详细操作见[网络接入与防护](/features/network)。

## 扫描感知

打开 **安全中心 → 扫描感知**，检查 bpftrace、root 与 ufw 的状态，点击 **安装探针**，再启动并观察连接记录。出现误封时从封禁清单中解除来源；停用时先停止探针，再核对现有防火墙规则。

- **探针**：`bpftrace` 脚本采集半开连接（SYN），按来源和目标端口汇总。
- **默认阈值**：单来源 12 个不同端口。命中后写入 `ufw` 拒绝规则并记录到本机封禁清单。
- **运行方式**：探针由受控端监管，进程退出即重启；daemon 重启后已安装的探针自动恢复。
- **操作**：安装 / 启动 / 停止探针，查看观测到的连接，解除单个来源的封禁。

## 主机探测

打开 **安全中心 → 主机探测**，输入已获授权的 IP 地址或主机名，选择探测项目并提交。到 **任务** 页查看进度和报告；需要结合公网情报时启用 Shodan InternetDB。

- 目标只接受字面 IPv4 / IPv6 或 RFC 1123 主机名；网段、列表、任何可能被读成 nmap 参数的值都会被拒绝。
- `nmap` 以 argv 调用，不经过 shell；IPv6 目标自动加 `-6`。
- 系统指纹需要 root，且 IPv6 的指纹库覆盖较差，结论为空时报告会如实写出。
- 可叠加 Shodan InternetDB 的免密钥被动情报；它没有 IPv6 索引，v6 目标只返回主动扫描结果。

扫描耗时以分钟计，因此注册为任务执行，结果写入任务详情。

::: warning 授权范围
探测会暴露面板自身的 IP。只对你有权测试的目标使用；被动情报来自第三方，仅作参考。
:::

## 蜜罐

在 **安全中心 → SSH / Web 蜜罐**（或 SSH/WAF 页的蜜罐入口）选择模式，先为该模式点击 **构建镜像**，再选择宿主机尚未占用的 `1024–65535` 端口，确认公开并启动。Web 与 SSH 镜像分别构建；任务进度在 **任务** 页查看，运行状态及停止操作在蜜罐页。服务端不会修改防火墙或生产 SSH/WAF 监听地址；如需外部访问，请自行放通所选端口。没有 `/dev/kvm` 时使用软件模拟，启动较慢。

- **Web 入口**：对 `GET /` 返回静态状态页，其他请求返回 404。
- **SSH 入口**：接受 SSH 连接、发送 SSH 标识后断开；不进行密钥交换、身份认证或提供 shell。它适合验证探测流量到达，不采集登录凭据。
- **隔离**：guest 使用受限 QEMU 用户态网络，无宿主设备透传、无默认路由；每次启动须明确选择独立端口。对公网开放前先检查防火墙和上游网络策略。

## 文件防篡改

打开 **安全中心 → 文件防篡改**，按文件系统和防护需求选择模式：

1. **chattr 不可变保护**：底部点击 **保护路径**，选择文件或目录；维护前解除保护，完成后重新添加。目录会递归设置不可变属性。daemon 启动时从清单复查并重新应用。
2. **eBPF 持续防护**：在持续防护卡片添加 ext 文件系统上的普通文件。需要 root、已启用的 BPF LSM、挂载的 bpffs，以及安装的 `libbpf` 和随 daemon 发布的加载器。页面分别显示路径身份是否匹配、内核 inode 规则是否生效；状态退化时按提示检查并重新添加。最多 64 个 inode；硬链接指向相同 inode 时同样受保护。重启后 daemon 启动时恢复规则，启动前并无此保护。已存在的可写映射和底层设备直接写入不在保护范围内。
3. **eBPF 写入观察**：对普通文件进行一次约 5 秒采样，统计 `vfs_write` 调用，用于排查；不添加持续保护规则。

移除 eBPF 规则与解除 chattr 属性是两个独立操作。

## 主机加固

打开 **安全中心 → 主机加固**，逐项查看当前值与建议值，再按需应用。批量使用 **应用全部建议值** 前先检查 `sudo`、`umask` 和内核参数对现有服务的影响。配置写入受管文件，重启后继续生效。

| 项目 | 说明 |
| --- | --- |
| 空链接 | 精确匹配目标无法解析的链接，删除前再解析一次，避免误删刚修好的链接 |
| 默认 umask | 写入 `pam_umask` 使用的配置文件；校验要求「其他用户必须失去写权限」，`027` 有效、`000` 被拒绝 |
| at / cron | 写 `*.allow` 并删除 `*.deny`，用户名逐条校验 |
| sudo | 只写入 `use_pty` 与 `!visiblepw`，写入后用 `visudo -c` 校验，不通过则回滚 |
| 内核参数 | 只暴露 15 个有明确安全含义且有安全取值的参数；取值写入 `sysctl.d` 并用 `sysctl -w` 立即生效 |

`net.ipv4.ip_forward` 被标为**需人工判断**，不包含在「应用全部建议值」里：在容器宿主或路由器上关闭转发会直接破坏网络。

## SELinux

在 **安全中心 → SELinux** 先看当前模式与初始化状态。有 SELinux 的主机可在五个标签页中管理策略：

- **概览**：当前 / 开机模式、策略类型、模块数量与列表。
- **布尔开关**：带搜索的逐项开关，只接受策略实际声明的名字。
- **文件上下文**：本地定制可增删；保存后执行 `restorecon -R` 重打标签，因为 `semanage` 只记录规则、不改现状。
- **端口标签**：查看端口与类型的绑定，可绑定 / 解绑。
- **拒绝日志**：展示权限、`tclass`、源 / 目标上下文与路径。

### 首次初始化

在从未打过标签的主机上直接切换到 enforcing 会让机器无法启动。因此初始化是页面上一个显式步骤：

1. 为面板自身路径与容器存储写入文件上下文规则。
2. 对全盘执行 `restorecon -R`，但**显式排除容器存储**——overlay 层里是完整的 guest 文件系统，把宿主策略盖上去会让容器内的文件失去可执行权限。
3. 写入就绪标记。

未完成初始化时，enforcing 开关不可用，受控端也会拒绝「未初始化 → 切 enforcing」这条路径。

### 重打标签之前禁止重启

未初始化的主机重启后会回到无法启动的状态。因此就绪标记存在之前，面板拒绝一切会把主机带下去的操作：对 `reboot` / `poweroff` / `halt` / `kexec` 目标及其服务形态一律返回可读错误，并指向初始化入口；普通服务不受影响。主机没有 SELinux、没有 `semanage` 或已完成初始化时一律放行。

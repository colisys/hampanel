# 商店概览

在客户端打开 **应用商店**，按需要选择以下入口：

| 入口 | 装的是什么 | 依赖 |
| --- | --- | --- |
| **Compose 应用** | 内嵌 Compose 模板，参数化部署 | 可用的 Docker 或 Podman |
| **系统工具** | 宿主软件包 | Linux 包管理器（apt/dnf/yum/zypper/pacman/apk） |
| **Nix** | `nix build` / `nix run` | 服务器已装 Nix |

Windows 受控端可在具备容器引擎时使用 Compose 应用。系统工具安装需要 Linux 包管理器；Nix 操作需要服务器已安装 Nix。

## Compose 应用

1. 打开 **应用商店 → Compose 应用**，用搜索或分类找到应用，打开卡片确认运行依赖及占用端口。
2. 点击 **部署**，填写模板中的端口、账号、密钥等参数。密码类参数留空会自动生成；部署结果会显示实际使用的密码，请及时保存。
3. 在 **任务** 页查看部署进度与输出。部署失败时检查端口冲突、容器引擎和镜像拉取信息，再重新提交。
4. 部署成功后从应用卡片查看状态、日志和启停操作。修改配置可选择 **使用新参数重新部署**，然后检查项目运行状态。

预置模板部署后会生成 Compose 项目，也可在 **容器 → 编排** 管理。

### 分类与筛选

列表顶部有搜索框与分类标签。分类来自应用登记的 `category` 字段，点选后只显示该分类的应用；搜索同时匹配名称、标识、描述与分类。两者可叠加，清除后恢复全部。

### 部署后的入口

多数应用只监听模板里配置的端口。有些应用还要求额外步骤：

- **Bark**：不支持 mTLS，公网访问需在 WAF 中为它添加域名路由，或接入你自己的反向代理。
- **Certbot**：standalone 模式需要 80 端口空闲，签完证书再到站点中引用证书文件。
- **vLLM**：需要 NVIDIA GPU、驱动与容器工具包。
- **ComfyUI**：CPU 版，首次部署从官方源码构建，模型需自行导入。
- **Act Runner**：挂载容器引擎 socket，等效授予宿主机控制权限。
- **EasyTier**：使用宿主网络、TUN 与 `NET_ADMIN`，可能改写宿主路由。

完整清单见[应用目录](/store/catalog)。

## 卸载与数据

| 操作 | 结果 |
| --- | --- |
| 停止 | 容器停止，数据保留 |
| 卸载（保留数据） | 移除容器与编排，命名卷保留 |
| 卸载并删除数据 | 一并删除命名卷，数据不可恢复 |

::: warning 卸载前备份数据
选择 **卸载并删除数据** 会删除命名卷。先备份数据库、模型或其他需要保留的内容。
:::

## 在编排页管理

商店部署的项目同时出现在「容器 → 编排」中。可以在那里查看项目状态、编辑编排、单独拉取镜像，或做更细的管理。
